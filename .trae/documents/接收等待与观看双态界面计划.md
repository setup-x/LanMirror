# 接收等待与观看双态界面计划

## 概要

单路与多路接收统一改为：等待时仅显示浅色连接信息，不露黑色或深灰色空窗口；收到首帧提交通知后自动进入观看，仅保留投屏窗口及窗口内必要控件。HUD
保留延迟与 FPS，第二行仅显示传输网速 Mbps，不再显示超时缺片。发送页不变。

## 当前状态

- `app/src/main/java/com/lanmirror/app/MultiReceivePanel.java` 已有四个持久 Surface、首帧回调与会话
  ID 校验；连接即参与布局，首帧只撤遮罩，外围信息仍存在。grid、tile、cover 仍用深色背景。
- `app/src/main/java/com/lanmirror/app/MainActivity.java` 单路启动即显示黑色
  preview，上部为连接信息/设置；观看依赖手动全屏。不能将 onVideoSize 视为首帧。
- `lanmirror-receiver/src/main/java/com/lanmirror/receiver/api/ReceiverSession.java` Listener
  只有状态与尺寸；同一接收实例接受多次连接，Activity 的 receiverGeneration 无法区分实例内重连。
- `lanmirror-receiver/src/main/java/com/lanmirror/receiver/internal/SmoothReceiverImpl.java` 使用
  AsyncSurfaceDecoder，后者已有 onFirstFrameRendered；同步 ReceiverSessionImpl 则在 drainOutput
  成功提交输出处可发通知。
- `app/src/main/java/com/lanmirror/app/StreamHud.java` 短标签与详情共用传输格式，需要分离，避免删除详情诊断信息。

## 实施步骤

### 1. 单路增加连接级显示事件（不改变接收行为）

涉及 ReceiverSession.java、ReceiverSessionImpl.java、SmoothReceiverImpl.java。

- Listener 新增默认方法 onConnectionStarted (long connectionId)、onFirstFrame (long connectionId)
  、onConnectionEnded (long connectionId)，现有调用者无需修改。
- 每个监听 Worker 内为接受的连接生成单调递增 ID；开始通知在启动该连接的解码处理前发出，结束通知在 peer
  清理路径发出。终止监听与主动 stop 时 Activity 自行恢复等待，不依赖已取消的后台通知。
- 同步管线：DecodeSession 内保留连接级一次性首帧标记；成功 releaseOutputBuffer (index, true) 后首次通知。不因
  flush/重建 decoder 重置连接首帧标记，不更改渲染判断或统计。
- 异步管线：转发已有 onFirstFrameRendered；Session 内一次性标记，且校验 Worker live、Session 当前身份及未
  closed，避免旧 decoder 延迟回调影响新连接。
- Activity 在 UI 线程处理三种事件，校验 receiverGeneration、mode、receiverWanted，以及
  connectionId。保留最高已结束 ID 的屏障：迟到的开始/首帧不能恢复已结束或旧连接。新连接开始重置尺寸与首帧状态。
- 首帧语义为已成功提交到 Surface，并非物理面板刷新完成；不引入新编解码策略。

### 2. 多路等待与观看

涉及 MultiReceivePanel.java。

- root 内新增持久 FrameLayout 承载区，底层放现有 AdaptiveGrid/四个 tile，上层放全覆盖浅色不透明连接信息面板。所有
  Surface 及祖先始终 attached、VISIBLE，不能通过 GONE、移除或重建 Surface 实现等待。
- 将现有设备名、地址、端口、摘要、发现状态、说明和结束按钮放入覆盖面板，等待时只露这些信息；浅色底与白卡风格延续现有二级页。
- 以任一路 activeId > 0 && firstFrame && !quarantined 判定有可观看画面。首次成立自动撤连接面板；最后一路不可观看时恢复面板。其余新连接仍按现有
  activeId 布局并以浅色连接遮罩等待首帧，避免深色空窗。
- 首帧、槽位变化、quarantine、用户断开、Surface 销毁及 pause 都重算显示状态；保留现有会话校验、焦点清理与审批队列。
- 分离观看态与 focus：观看态隐藏外围连接信息，保留 tile 标题/HUD/选声；focus
  继续独立放大及现有标题收起行为，不能因自动观看而把选声按钮清零。
- tile/grid/chrome 改浅色深字；实际视频区及视频比例留边保持黑色，仅在观看时可见。
- 等待覆盖层拦截底层触摸及无障碍访问。用户可从 tile
  报告弹窗进入连接信息/全部状态；有可观看画面时面板提供“继续观看”，否则不可强制露出空窗。手动查看信息不被普通指标更新打断；全部断开后下一次首帧重新自动观看。
- 普通多路观看保留系统栏，focus 隐藏系统栏；等待/连接信息态显示浅色系统栏。退出和返回主页显式恢复系统栏可见性及
  immersive flags，不只修改颜色。

### 3. 单路等待与观看

涉及 MainActivity.java。

- previewBox 改为持久 FrameLayout，Surface 为底层居中子项，完整浅色连接信息/设置面板为上层。初始构建先显示覆盖层，不能露初始黑窗。
- fitPreview 同步改用 FrameLayout.LayoutParams 与 Gravity.CENTER，继续按原比例适配。
- 当前连接首次提交画面时自动进入沉浸观看；观看只显示视频窗口。点击画面或返回键显示连接信息，当前连接已出画面时可“继续观看”；无首帧不能手动进入空窗。
- 收到当前连接结束、停止、切换管线/解码实验、Surface 销毁或暂停时恢复等待覆盖层，清理首帧及连接身份。旧通知不能切回观看。
- 将现有连接信息、状态报告、设置和结束接收操作保留在面板内；等待时信息区可滚动使用可用空间，不继续沿用只占
  40% 高度的限制。
- 状态文字仍按现有方式更新，但不解析文字决定观看/断开；仅使用结构化连接事件。
- 信息态显示浅色系统栏，观看态隐藏系统栏，回主页显式恢复。保留旋转、生命周期与退出处理，不改变端口、配对码和权限流程。

### 4. HUD

涉及 StreamHud.java、MultiReceivePanel.java、tests/com/lanmirror/app/StreamHudFocusTest.java。

- 正常 HUD 第一行保持估算延迟与实际提交 FPS，第二行仅为“xx.xx Mbps”；无指标或过期为“-- Mbps”，不能保留旧网速。
- 分离速率短标签和诊断详情格式。详情保留超时缺片、TCP 不适用及统计口径；界面提示删除针对 HUD
  缺片的说明，保留接收视频载荷网速口径。
- 不改计数与采样：这里是实际接收视频载荷速率，不是链路测速，不含音频/协议头；UDP 包含重复和重传。
- TileBox 宽度参考同步去掉缺片文字，仍按字体/可用宽度固定 2/4 行，不能根据实时值改变高度导致 Surface
  抖动。
- 更新现有 HUD 测试：短标签不含缺片/TCP 丢包文字，详情仍保留诊断，验证正常、零速率、未知及过期状态。保留原
  focus/reuse 断言。

## 假设与边界

- 用户已确认单路、多路都改；HUD 只替换超时缺片，延迟和 FPS 保留。
- 保留多路审批弹窗、逐路选声、报告及放大/返回语义，不把“仅窗口”解释为删除窗口必要操作。
- 不改传输协议、编解码决策、音频、权限、发现或会话释放语义；新增 Listener 通知仅供 UI 显示状态使用。
- 不修改 gradle.properties，不提交、不卸载，不主动生成 APK；已有工作区其他变更不得回滚。
